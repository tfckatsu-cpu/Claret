# S2. Целостность профиля Hotbuild — расследование и предложение

Дата: 2026-11-18. Режим: только чтение; код модов не изменялся. Артефакт репродукции: `Tests/hotbuild-profile-corruption.lua` (не входит в список раннера).

## 1. Репродукция

Сценарии:
- **A** — в профиле пресетов один валидный и один битый (`grid = {}` без `buildings`/`units`).
- **B** — пресеты валидные, в профиле клавиш одна запись с неизвестным полем.
- **C** — пресеты валидные, в профиле контекстов одна строка без действия.

Во всех трёх: валидные данные загружаются, но клавиши не применяются (движковый keymap пуст), ни одно сохранение не проходит, редактирование клавиш заблокировано.

## 2. Точная цепочка отказа

1. `Runtime.Create` (`Runtime.lua:101-121`) читает три профиля и создаёт `Model`, `ContextModel`, `KeyboardBindings`.
2. `Model.Create` (`Model.lua:300-330`) отбраковывает битую запись с предупреждением, валидные грузит. Сам по себе он не блокирует ничего.
3. `ContextModel.Create` (`ContextModel.lua:71-74`, `223-225`): **первое** же предупреждение (любая битая строка, неизвестные поля, версия, >64 записей) ставит `readable = false`; `CanSave()` = `readable and actionCatalog`.
4. `KeyboardBindings.Create → Migrate` (`KeyboardBindings.lua:275-280`):
   - `LoadPairs()` возвращает `nil` при **любой** структурной проблеме — битый chord, не таблица, неизвестное поле в паре, нестроковое значение, несовместимая double-пара (`KeyboardBindings.lua:248-273`) → `pairError = s004`;
   - либо, если у `Model`/`ContextModel` есть **хоть одно** предупреждение → `pairError = s005` («Повреждён профиль Hotbuild; перенос клавиш отключён») и **return до применения**.
5. `KeyboardBindings.lua:917-918`: `if pairError then WARN(...) end; if not pairError then service:Refresh() end` — keymap не перестраивается.
6. `service:Start` → `RefreshKeys` (`Runtime.lua:247-256`): предупреждения `Model`/`ContextModel` → `false` (`runtime.s004`); `pairError` → `false`. Значит, `Keys:Apply` не вызывается вообще: ни один пресет не регистрируется.
7. Сохранения:
   - `Set/Clear/SetDouble/ClearDouble/ClearChord/ClearPresetAssignments/ClearCompositeAssignments` — все начинаются с `if pairError then return false,pairError end` (`KeyboardBindings.lua:357, 379, 419, 719, 745, 772, 834`);
   - `Commit` (`Runtime.lua:664-668`) — `pairError` → отказ; предупреждения `Model` → `s018`;
   - `CommitContext` (`Runtime.lua:715-720`) — `pairError` → отказ; `not CanSave()` → `s022`; предупреждения `Model` → `s023/s024`.

Итог: один битый record в любом из трёх профилей включает режим «всё заморожено».

## 3. Корневая причина

Три независимых канала предупреждений трактуются как **глобальный стоп**, а не как карантин записи:

1. `Model` предупреждения (per-record) → блокируют `RefreshKeys`, `Commit`, через `Migrate` ещё и клавиши.
2. `ContextModel.readable` (per-record) → блокирует `CanSave`, `RefreshKeys`, `Migrate`.
3. `LoadPairs` — **all-or-nothing**: любая структурная аномалия обнуляет весь профиль клавиш и ставит `pairError`, который блокирует все операции с клавишами.

Дополнительно `Migrate` смешивает разные вещи: «мой профиль клавиш битый» и «в профиле пресетов/контекстов были предупреждения» (s005).

**Скрытая ловушка при наивном снятии гейта** (важно для правки):
- `Model:Export` (`Model.lua:190-192`) и `ContextModel:Export` (`ContextModel.lua:212-215`) возвращают только валидные записи → сохранение молча **стёрло бы** отбракованные записи из профиля.
- `Keys:Apply` (`Keys.lua:79-100`) удаляет все действия `ClaretHotbuild_*` категории «Claret Hotbuild», которых нет в `wanted`, и вместе с ними записи `UserKeyMap`/`UserKeyDebugKeyMap`. После снятия гейта первый же `RefreshKeys` тихо удалил бы назначения карантинных пресетов из FAF-таблиц.
- `KeyboardBindings:Refresh` (`KeyboardBindings.lua:884-891`) кидает `error()`, если у записанного Claret-id нет определения; при карантине это снова валит Refresh.

Поэтому минимальная правка — это карантин **плюс** сохранение сырых записей и id в FAF-таблицах, а не просто удаление гейтов.

## 4. Какие данные и операции затронуты

| Данные | Формат | Что происходит сейчас |
|---|---|---|
| `ClaretHotbuild` | `{version=1, bindings[]}` | битая запись → предупреждение; при любом предупреждении блокируются все сохранения пресетов |
| `ClaretHotbuildContexts` | `{version=1..3, bindings[]}` | битая запись → `readable=false` → `CanSave=false` |
| `ClaretHotbuildKeyboard` | `{version=1..2, assignments{}}` | любая структурная аномалия → `LoadPairs=nil` → `pairError` |
| FAF `UserKeyActions`, `UserKeyMap`, `UserKeyDebugKeyMap`, `keyDescriptions` | таблицы профиля | сегодня не трогаются (гейт), после наивного снятия — чистка |

Заблокированные операции: применение всех клавиш Hotbuild; создание/правка/удаление пресетов; создание/правка/удаление контекстов; любые операции с назначениями клавиш (включая двойные нажатия). Продолжают работать: чтение и показ валидных данных, открытие меню и редакторов, остальные моды.

## 5. Предлагаемая минимальная правка

Принцип: **карантин записи, а не остановка подсистемы**; ничего не удалять и не перезаписывать без явного действия пользователя.

1. **`Model.lua`**
   - Хранить отбракованные записи как есть (`quarantine = { {raw=..., reason=...} }`), предупреждения — для диагностики.
   - `Export()` = валидные записи + сырые отбракованные в исходном порядке (ничего не теряется; при повторной загрузке они снова попадут в карантин, предупреждение сохранится).
   - Блокировать запись только при нечитаемой **форме** профиля (не table, `version ≠ 1`, `bindings` не list) — отдельный флаг `CanWrite()`.
2. **`ContextModel.lua`**
   - `readable` заменить на `profileShapeReadable` (только форма/версия/неизвестные поля верхнего уровня); per-record предупреждения больше не влияют.
   - `CanSave()` = каталог доступен **и** `profileShapeReadable`.
   - `Export()` — как у `Model`, с сырыми записями.
3. **`KeyboardBindings.lua`**
   - `LoadPairs()` → per-record карантин: битый chord пропускается с сообщением, остальные грузятся. `nil` остаётся только для нечитаемой формы/версии профиля.
   - `pairError` сохраняет смысл «пары недоступны» (нужен для fallback в `Runtime.Execute`), добавляется `GetPairWarnings()`.
   - Запись keyboard-профиля блокируется только при нечитаемой форме; per-record карантин запись не блокирует.
   - `Refresh`: вместо `error()` — пропуск с записью в лог (это же закрывает HOT-10, без которого карантин снова валит Refresh).
4. **`Migrate`** — убрать гейт `s005`; миграция legacy-ссылок работает по валидным пресетам, остальные не трогает.
5. **`Runtime.lua`** — убрать гейты по предупреждениям в `RefreshKeys`, `Commit`, `CommitContext`; оставить: `Commit` зависит только от формы preset-профиля, `CommitContext` — только от формы context-профиля и каталога; `pairError` больше не блокирует сохранение пресетов/контекстов.
6. **`Keys.lua`** — в `Apply`/`ApplyAbsolute` включать в `wanted` id карантинных пресетов/композитов, чтобы их действия и назначения не вычищались.
7. **Диагностика** — в редакторе пресетов показывать число и первую причину проблем (сейчас предупреждения `Model` не видны нигде; `ContextEditor` показывает только первую строку).
8. **Опционально, отдельным шагом** — «Удалить повреждённые записи» с явным подтверждением (единственный путь удаления; по умолчанию данные сохраняются).

Гарантии: профиль не пишется при нечитаемой форме; сырые записи сохраняются при любом сохранении; действия и клавиши карантинных записей не удаляются; запись идёт через `candidate` + rollback, как сейчас.

## 6. Совместимость

- Чтение версий 1/2/3 не меняется; формат экспорта не меняется (сырые записи добавляются как есть).
- Legacy-миграция `grid.context` сохраняется без изменений.
- Неизвестная будущая версия профиля → только этот профиль становится read-only, без перезаписи; остальные функции работают.
- UID, id пресетов/контекстов и строки действий не меняются.

## 7. Риски предлагаемой правки

| Риск | Оценка | Смягчение |
|---|---|---|
| Сырые записи при экспорте могут снова дать дубль id (дубликат уже отбракован при загрузке) | низкий | дубликат сохраняется как есть, предупреждение остаётся; данные не теряются |
| Карантин «замораживает» предупреждение навсегда, пока пользователь не исправит | средний | видимая диагностика + отдельный инструмент удаления (шаг 8) |
| Сохранение теперь разрешено при битых записях → можно записать профиль с теми же битыми записями | низкий | сырые записи переносятся без изменений, валидные — под валидацией |
| `Keys:Apply` сохраняет id карантинных записей → в F1 остаются «мёртвые» действия | низкий | лучше, чем тихое удаление; можно помечать как obsolete |
| Снятие гейтов открывает больше путей записи | средний | отдельные shape-гейты + существующий rollback + регрессионные тесты |

## 8. Предлагаемые регрессионные тесты

База — `Tests/hotbuild-profile-corruption.lua` (сейчас фиксирует текущее поведение; после правки утверждения инвертируются).

1. **A (пресеты)**: валидный + битый пресет → валидный применяется (в keymap есть клавиша), сохранение проходит, битая запись остаётся в профиле после сохранения, предупреждение видно.
2. **A2**: два пресета с одинаковым legacy `key` → сохранение проходит, обе записи сохранены.
3. **B (клавиши)**: битая пара + валидные пары → валидные применяются, битый chord пропущен, keyboard-профиль не перезаписан (или перезаписан с сохранением сырой записи), сохранение пресетов проходит.
4. **C (контексты)**: битая строка + валидный контекст → `CanSave` = true, сохранение контекста проходит, сырая запись сохранена.
5. **D (версии)**: preset v2 / contexts v4 / keyboard v3 → соответствующий профиль read-only, остальные работают, файл не перезаписан.
6. **E (форма)**: значение профиля — строка/число → предупреждение, ничего не пишется, остальное работает.
7. **F (FAF-таблицы)**: после `RefreshKeys` действия и назначения карантинного пресета не удалены.
8. **G**: `Refresh` не кидает ошибку при отсутствии определения (HOT-10).

## 10. Реализация (2026-11-18)

- `Model.lua`: упорядоченный список `entries` (валидные + сырые), `quarantine` с index/id/reason, `Export` сохраняет сырые записи на месте, `CanWrite()` для формы/версии, `GetQuarantine()`, `GetQuarantinedIds()`; гейт по предупреждениям убран.
- `ContextModel.lua`: `shapeError` вместо `readable`; per-record карантин; `CanSave` = каталог + форма; `Export` с сырыми записями; `Put/Delete` учитывают порядок.
- `KeyboardBindings.lua`: `LoadPairs` — per-record карантин (битый chord пропускается), только форма/версия дают `pairError`; `Profile` сливает сырые записи и удаляет только управляемые; `Migrate` без s005; назначения на карантинные пары не считаются ошибкой и сохраняются; `Refresh` без `error()`; `GetPairWarnings()`.
- `Runtime.lua`: `RefreshKeys` применяет валидные данные и не пересобирает keymap при нечитаемом профиле клавиш; `Commit`/`CommitContext`/`ValidatePreset` больше не зависят от чужих предупреждений; удаление пресета не блокируется профилем клавиш.
- `Keys.lua`: `Apply` сохраняет id карантинных пресетов — их действия и назначения не вычищаются.
- `Editor`/`ContextEditor`/`KeyboardEditor`: компактная строка `hotbuild.problems.summary` (EN/RU) с числом и первой причиной.
- Тесты: `Tests/hotbuild-profile-corruption.lua` переписан под новое поведение и добавлен в раннер; в `hotbuild-context-model.lua` и `hotbuild-context-runtime.lua` старые ожидания «глобального стопа» заменены на карантин.

Результаты: целевой тест — 1/0; полный прогон — **49/14** (те же 14 прежних падений, новых нет).

Остаточные риски и ограничения:

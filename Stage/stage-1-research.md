## Составные контекстные бинды Hotbuild (2026-11-10)
### Реализация и правила
- Добавлены `ContextActions.lua`, независимая модель `ContextModel.lua` и редактор `ContextEditor.lua`. Отдельный раздел меню «Составные бинды» хранит наборы в профиле `ClaretHotbuildContexts`; ссылка из сетки Hotbuild хранится в прежнем профиле `ClaretHotbuild` как `grid.context`. Сохранённая ссылка не включает составной набор в список обычных `entries`.
- Действия каталога сверены с `modules/ContextActions.lua`: выбор/переход к ACU; выбор ближайшего свободного инженера T1 или инженеров на экране, воздушного разведчика, транспорта, радаров/сенсоров; выбор всех воздушных разведчиков; цикл добытчиков массы на экране/карте; улучшение одного выбранного добытчика; overcharge, перевозка, reclaim, guard, move, attack, attack-move, nuke/tactical, repeat queue, pause, shield/stealth, stop/soft stop, удаление последнего заказа, а также «Взорвать Fire Beetle» (только если каждый выделенный юнит имеет Blueprint ID `xrl0302`). Hotbuild 0.10.1 требует Core >= 0.10.0. Действие «Добавить следующий юнит в груз» принадлежит Core и сохраняет стабильный ID `append_transport_cargo`. Core использует нативные API FAF `GetAttachedUnitsList`, фильтр `categories.MOBILE` и `AddToSessionExtraSelectList`, чтобы добавлять по одному уже загруженному мобильному юниту в список выборочной выгрузки для последующего штатного приказа. Это подготовка выбора, а не непосредственная команда выгрузки. Шаг сбрасывается при смене выделения или состава груза; общий список дополнительного выделения Core не очищает. Для действия не нужны `ReUI.Construction` или `ReUI.Actions`; сам Core по-прежнему требует ReUI. Цикл добытчиков массы на экране/карте восстанавливает первоначальное выделение при отсутствии подходящих целей или ошибке перебора. Доступность фильтруется по выбранному контексту и повторно проверяется во время исполнения. Добавлены улучшения ACU: инженерия, RAS, телепорт, оружие, защита и специальное (с фракционными соответствиями); для SACU — инженерное улучшение через `ContextEnhancements.lua`. План строгий: выделен ровно один живой юнит, он должен оставаться тем же единственным выделенным юнитом; целевой blueprint enhancement и полная цепочка prerequisites проверяются в одном слоте. Сверяются установленное улучшение, очередь и ограничения технологий; неверная цепочка, слот, порядок очереди, запись удаления, ограниченное, отсутствующее или уже завершённое улучшение отклоняются. Команда ставит оставшиеся звенья через append, не очищая очередь и не подменяя автоматически другое улучшение. Логика локально проверена; фактическое принятие приказа и все варианты требуют проверки в матче.
- Контексты: пустое выделение, ACU, SACU, инженер, завод, транспорт, тактическая и стратегическая ракетные шахты, добытчик массы, разведчик и прочие юниты. Шахты разделяются по `TECH3`; Blueprint `xsb2401` явно распознаётся как стратегический. Запуск `tactical` только для тактической шахты, `nuke` только для стратегической; `stop` есть для обеих. Fire Beetle не выделен в отдельный контекст: действие детонации находится в `other` и доступно только при составе выделения из юнитов с Blueprint `xrl0302`. Контекст определяется только для однородного выделения; смешанное становится `mixed` и не запускает составное действие. Для смешанного выделения остаётся обычный путь Hotbuild.
- Приоритет Runtime: для ACU и других не-инженерных выделений сначала выполняется строка составного бинда; для инженера сначала ищется доступная постройка из Hotbuild, и только при её отсутствии пробуется контекстное действие. Для пустого выделения действует отдельная строка, в том числе выбор/переход к ACU.
- Клавиша назначается после сохранения Hotbuild через штатные настройки клавиш FAF, по имени бинда в категории Claret Hotbuild; конфликты клавиш разрешаются в меню игры. Предупреждения при загрузке старого или неподдерживаемого профиля Hotbuild блокируют операции, способные удалить или переинициализировать его данные, включая массовую очистку назначений клавиш, поэтому сохранённые назначения защищены до восстановления профиля. Удаление набора отклоняется, пока на него ссылается сохранённый Hotbuild; ссылку сначала нужно убрать и сохранить. Повреждённый/неподдерживаемый исходный профиль контекстов блокирует запись (`CanSave`), а Runtime блокирует сохранение и удаление при предупреждениях о повреждённом/неподдерживаемом старом профиле Hotbuild; исходные данные и назначения клавиш не перезаписываются молча. ID/действия/контексты, уникальность контекста, лимит 64 записи/строк и глубокое копирование проверяются моделью.

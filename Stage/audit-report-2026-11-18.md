## 2. Архитектура как она есть

### Core

- Вход: `Main.lua` → `ReUI.Require` (ReUI.Core ≥ 1.7.0, ReUI.UI, ReUI.Options ≥ 1.2.0, версия игры ≥ 3816; установлен FAF3840 — совместимо).
- Порядок: `OnPreCreateUI` (`MenuKey.Initialize` + вкладка F10 → Claret) → `OnPostCreateUI` (Group на `GetFrame(0)`, Registry, регистрация фич, Welcome, `uiReady = true`) → `OnDestroy` (последовательная цепочка очистки).
- Публичный API: `RegisterFeature`, `RegisterSettingsSection`, `Localization`, `IsMenuOpen`, `IsKeyCaptureActive`, `AppendTransportCargo`, `CreateStrategicRing`; `GetFeatureState` экспортирован, но вызывающих нет.
- `Registry` + `Lifecycle` — самая зрелая часть: scope (`Defer/Own/Guard/Bind/Every`), защита от реентрантности, состояния disabled/running/error/disposed, обратный порядок очистки с `pcall`.
- **Факт: достижимо в продакшене 14 файлов / 2 899 строк. Не достижимо — 27 модулей / 6 735 строк (70 % кода):** все `Construction*` (16 файлов), `Orders*` (6), `Multifunction*` (2), `SelectionIgnore*` (2) и `CargoSelection`. Ни `Main`, ни меню, ни Hotbuild их не импортируют и не регистрируют; их грузят только тесты (31 файл). Это отложенная реализация запланированной замены ReUI-HUD (решение пользователя 2026-11-18): код и тесты сохраняются, интеграция вне текущего скоупа (см. §8, R6).
- `rawget(module, 'IsIgnoredSelection')` в хуке `OnSelectionChanged` читает функцию, которую ставит патч ReUI; собственный менеджер ignore (`SelectionIgnoreHook`) в продакшене не устанавливается.

### Hotbuild

- Вход: `Main(isReplay)` → локализация → 4 хука (`hotkeylabels.getKeyTables`, `gamemain.OnSelectionChanged`, `ClaretCore/modules/MenuKey.lua#Open`, `keybindings.CloseUI`) → `RegisterFeature('hotbuild', …, options.enabled)` → секция настроек с Navigator (Keyboard / Hotbuild / Contexts) → `OnPostCreateUI`-владелец с `OnDestroy`.
- Поток нажатия: клавиша → действие FAF keymap (`UI_Lua … Runtime.Execute(id, IsKeyDown(16))`) → `Dispatch` (гейты: `active`, replay, key-capture) → `Execute*` → `Adapter:Context` (выделение, ордера, завод) → разрешение контекста (land/air/navy → empty → acu/sacu/engineer → factory → silos → transport/mex/scout/other) → `ContextActions` / `Model:Execute` / `Adapter:Build` (`IssueBlueprintCommand`, count 5 при Shift, `SetActiveBuildTemplate`).
- Shift обрабатывается в пяти независимых местах: строка действия `IsKeyDown(16)`, fallback `Runtime.Execute`, `Adapter` count, сборка chord, factory-shift intercept (`ExecuteFactoryShift`).
- Хранение: три профильных ключа со своими версиями — `ClaretHotbuild` (v1), `ClaretHotbuildContexts` (v3), `ClaretHotbuildKeyboard` (v2); плюс прямая мутация FAF-таблиц `UserKeyActions`, `UserKeyMap`, `UserKeyDebugKeyMap`, `keyDescriptions`.
- `Runtime.lua` — «god module» (819 строк, синглтон `current`): dispatch, четыре пути исполнения, три транзакции сохранения, жизненный цикл редакторов, диагностика.

### Межмодовые контракты

- 7 символов `ReUI.ClaretCore.*` используются Hotbuild — все существуют в 0.10.13. Но `Theme.lua` импортируется 7 файлами Hotbuild по прямому пути, а `MenuKey.Open` хукается напрямую: обе связи не версионированы (COR-15, HOT-18).
- Оба мода хукают `gamemain.OnSelectionChanged`; хуки применяются в порядке регистрации, семантика `ignored` у обоих совпадает (двойной `rawget` до вызова оригинала). Взаимный дефект не найден.

### Git-гигиена

- Ветка `dev`, 5 коммитов; незакоммичены только пере-переводы `Context/*.md` и `Stage/*.md` на английский.
- В корне проекта лежат неотслеживаемые `ClaretCore/` и `ClaretHotbuild/` — точные копии рабочих модов (и не в `.gitignore`), плюс старая черновая `Claret Core/`. Итого до четырёх копий одного кода: риск правки не той папки.

## 8. Пересмотренный план стабилизации (2026-11-18)

Основание: уточнения пользователя. Автоматически принятые по таймауту ответы аннулированы и в план не входят. Крупный рефакторинг не планируется; каждый шаг — изолированная правка с отдельным подтверждением. ## 9. Первая правка (S1.1): подписи клавиш Hotbuild — предложение к утверждению

**Находка:** HOT-01/TST-01. **Класс:** подтверждённый дефект (код + падающий тест + скан базового `lua.nx2`: 0 определений глобала `Colours`).

**Корневая причина.** `modules/BuildKeyLabels.lua` трижды читает `Colours.plain` (строки 35, 102, 112), но такого глобала нет ни в Claret, ни в базовой игре: нативный `lua/keymap/hotkeylabels.lua` использует локальную таблицу `colours` (white/yellow/orange/red). `Main.lua` вызывает `BuildKeyLabels.Build` внутри `pcall` и при ошибке молча возвращал нативные отношения — функция не работала и не оставляла следа в логе.

**Реализованная правка (2026-11-18):**
1. `LabelColours` — 8 комбинаций: plain `ffffffff` (нативный), Ctrl `ffd26060` (приглушённый красный), Shift `ffe8cf6e` (приглушённый жёлтый), Ctrl+Shift `ff4db6ac`, Alt `ffffbf80` (нативный), Ctrl+Alt `ffff7785` (коралловый вместо тёмно-красного), Shift+Alt `ff9ccc65`, Ctrl+Shift+Alt `ff7986cb` — тона с Shift взяты из `Theme.Colors.keyCombo*` (легенда редактора).
2. `ReadChord` вычисляет цвет по комбинации модификаторов; Shift больше не белый и не сливается с «без модификатора».
3. `Build` выбирает для показа клавишу без модификатора (белое отображение имеет приоритет); если обычных нет — первую по алфавиту; цвет берётся у выбранной записи, модификаторные chord остаются в метаданных.
4. В `Main.lua` при `not okLabels` — `WARN` вместо полного молчания.
5. Тест: устаревшая ассерта `S+Z` приведена к решению build 139 (только физическая клавиша) с комментарием-обоснованием; добавлены проверки Ctrl+Shift, Shift+Alt, Ctrl+Shift+Alt.

**Затрагиваемые файлы:** `../mods/ClaretHotbuild/modules/BuildKeyLabels.lua` (обязательно), `../mods/ClaretHotbuild/Main.lua` (только ветка ошибки).

**Регрессионные риски:** низкие. Изменение display-only, сохранённых данных не касается; `Merge` и фильтры `ReadChord` не меняются; цвета — строки ARGB, как в нативной игре. Если глобал `Colours` определял другой мод, цвета станут нативными — это и есть нужное поведение.

**Проверка:**
- Локально: `node Tests/check-core.cjs --only build-key` → `hotbuild-build-key-labels` зелёный; полный прогон — на один зелёный больше, новых падений нет.
- В игре: пресет со зданиями на клавише; выделить инженера или завод — на строительной плитке появляется буква клавиши; цвет по модификатору (белый/Ctrl жёлтый/Alt оранжевый/Ctrl+Alt красный); два пресета на один blueprint → первая клавиша с «+»; при `probeEnabled` нет `WARN` о подписях.

**Откат:** правка изолирована в одном модуле плюс одна строка лога — `git revert` или восстановление файла из зеркала.

## 10. Что не проверено

- Ни один сценарий не запускался в FAF; скриншоты не снимались. Всё — чтение кода и локальные прогоны Fengari.
- Приватные поля ReUI.Construction не сверены с установленной версией (в декомпиляции этой части нет).
- Глобал `Colours` проверен только по базовому `lua.nx2`; теоретически его мог бы определить другой мод — опираться на это нельзя.
- Производительность не измерялась; лимит «256 зданий» — намерение неизвестно (код принимает до 4096).
- Поведение `ConExecute` для строк keymap-действий (HOT-22) и категории Shift-записей (HOT-23) — только предположения.

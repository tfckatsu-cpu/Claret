# S3. Привязки и legacy-данные — фактическая модель и минимальный план

Дата: 2026-11-18. Режим: только чтение; код не менялся.

## 1. Вывод заранее

S3 в исходном объёме (миграция «трёх источников истины») **не нужен**: код уже консолидирован на pair-записях, а `key`/`grid.context` в пресете — исторические метаданные, которые никто не пишет и которые влияют только на fallback при нечитаемом профиле клавиш. Остаётся гигиена: мёртвая проверка дубликата legacy-ключа и документация модели. Риск — низкий, миграции и изменения схемы не требуются.

## 2. Фактическая модель данных (проверено по коду)

| Слой | Профиль | Роль сейчас |
|---|---|---|
| Pair-записи | `ClaretHotbuildKeyboard` (`assignments[chord] = {preset, composite, action, double*}`) | **единственный источник истины** для клавиш, контекстов и двойных действий |
| FAF-таблицы | `UserKeyMap`, `UserKeyActions`, `UserKeyDebugKeyMap`, `keyDescriptions` | движковое зеркало пар; перестраивается `Refresh` |
| Поля пресета | `ClaretHotbuild` → `binding.key`, `binding.grid.context` | **исторические метаданные**; не обновляются, читаются только в fallback |

Кто пишет:
- `KeyboardBindings` — пары (`WritePairs`/`WriteAssignment`, `Profile()`); при миграции легаси-карт контекст пары берётся из `preset.grid.context` (`KeyboardBindings.lua:350`).
- `Editor` — **никогда** не пишет `key` и `grid.context` (только клонирует их в черновик: `Editor.lua:449-455`).
- `Model:Put` — сохраняет то, что пришло (`Model.lua:129-165`).

Кто читает:
- Dispatch: пары (`Runtime.Execute` → `GetPair`).
- Совместимость: `PairedBindings(model)` собирает копии пресетов с **актуальным** `pair.composite`/`chord` (`KeyboardBindings.lua:460-472`); именно их получают `ValidatePreset` (`Runtime.lua:652`) и `CommitContext` (`Runtime.lua:725`), а `KeyboardBindings:Validate` собирает копию с контекстом-кандидатом (`KeyboardBindings.lua:517`).
- Fallback при `pairError` (профиль клавиш нечитаем): `Runtime.lua:295` и `KeyboardBindings.lua:522` берут `grid.context`.

Это уже зафиксировано тестами:
- `Tests/hotbuild-context-runtime.lua:821-834` — «pair dispatch ignores preset grid.context after migration» (контекст намеренно противоречит паре).
- `Tests/hotbuild-grid-editor.lua:267` — исторический `grid.context` переживает редактирование и перезагрузку.

## 3. Проверка находки HOT-13

| Утверждение аудита | Факт |
|---|---|
| `key`/`grid.context` пишутся только в выбрасываемые копии | **Подтверждено**: `PairedBindings` и `Validate` пишут в копии; редактор не пишет вовсе |
| Сохранённый пресет хранит старый контекст | **Подтверждено**, но это осознанное поведение: dispatch идёт по парам, тест это фиксирует |
| `Compatibility` валидирует не ту пару | **Опровергнуто**: `ValidatePreset` и `CommitContext` валидируют копии из `PairedBindings` с актуальным `pair.composite` |
| `Model:Put` бракует сохранение по устаревшему legacy-ключу | **Код есть** (`Model.lua:208`), но правило мёртвое: дубликаты отсекаются ещё при загрузке, а редактор никогда не пишет `key` |

## 4. Что реально осталось

**A. Удалить мёртвую проверку дубликата legacy-ключа** (`Model.lua:208`).
- Почему: ключи больше не авторитетны (пары владеют привязками); редактор их не пишет; проверка не может сработать при обычной работе.
- Побочный эффект сегодня: профиль с двумя одинаковыми `key` при загрузке даёт ложное «Повреждённых записей: 1» и прячет второй пресет (S2-карантин). После удаления оба загружаются нормально.
- Объём: 3 строки + тест.

**B. Задокументировать модель данных** в `ClaretHotbuild/README.md` (короткий раздел «Saved data»): пары — источник истины; `key`/`grid.context` — исторические метаданные, не обновляются; при откате на старую сборку привязки новых пресетов могут быть не видны.
- Объём: 4–6 строк.

**C. Не делать (рекомендация):**
- Не обновлять `key`/`grid.context` при сохранении «для downgrade»: при нескольких парах на один пресет значение неоднозначно, а запись в профиль на каждое изменение клавиш усложняет атомарность.
- Не менять схему/версию профилей и не выполнять миграцию: данные уже в актуальном виде, а старые поля безвредны.
- `Compatibility.GetTileWarning` используется только тестами, в UI не вызывается — оставить (не расширять задачу).

## 5. Риски

- Низкие: удаление проверки не влияет на dispatch, валидацию и сохранение; дубликаты legacy-ключей безвредны.
- Остаётся: у новых пресетов `key`/`grid.context` пусты, поэтому откат на сборку до 141 не увидит их привязок — это документируется, а не «лечится».

## 6. Проверка

Локально:
- новый тест: профиль с двумя пресетами и одинаковым `key` загружается без предупреждений, оба доступны, сохранение любого проходит;
- существующие тесты (`pair dispatch ignores grid.context`, `historical reference survives`) подтверждают независимость dispatch от метаданных.

В игре (после правки): назначить пресет на клавишу, сохранить, выйти в меню и вернуться — привязка на месте; удалить контекст, на который ссылается пара, — предупреждение о связанном пресете появляется (через `PairedBindings`).

## 7. Итог

S3 сокращается до двух небольших правок (A+B). Это снимает единственную реальную проблему (ложный карантин из-за legacy-ключа) и фиксирует контракт данных, не трогая пользовательские профили.

## 8. Реализовано (2026-11-18)

- Model:Put больше не отвергает дубликат legacy-ключа: профиль с двумя одинаковыми `key` загружается без предупреждений, сохранение любого пресета проходит; тест hotbuild-model обновлён (включая профиль с одинаковыми ключами).
- В ClaretHotbuild/README.md добавлен раздел «Saved data»: пары — источник истины, key/grid.context — исторические метаданные, ограничение при downgrade.
- Полный прогон: 66/0. Синхронизация и коммит — после проверки в игре.

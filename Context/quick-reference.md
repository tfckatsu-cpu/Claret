# Claret: краткая сверка

Этот файл — индекс, а не замена исходных заметок. Дата сверки: 2026-11-10. Сведения из friend-notes, prestudy-notes и community-notes — сообщения и предварительные выводы, требующие проверки; оригиналы оставлены для сверки.

## Цели и границы
- Экосистема отдельных UI-модов с общей основой, индивидуальным отключением функций и вниманием к производительности; решения об архитектуре принимает пользователь. Источник: ../Credits and more/goals.md, ideas.md, AGENTS.md.
- Рабочие моды — ../mods/ClaretCore и ../mods/ClaretHotbuild. Чужие моды и Context/sources — только чтение; собственный код писать заново. UI-only. Подробнее: AGENTS.md, Stage/stage-1-research.md.
- Визуальный ориентир и правила: ui-style.md и claret-ui-reference.png. Токены: ../mods/ClaretCore/modules/Theme.lua.
- Настройки и окна всех модов Claret добавлять через **F10 → Claret**, API `ReUI.ClaretCore.RegisterSettingsSection`, без вкладок Builder.AddOptions в ReUI Options. Общая реализация — `../mods/ClaretCore/modules/Menu.lua`; пример подключения — `../mods/ClaretHotbuild/Main.lua`. Контракт окон, сохранение и ограничения — Context/menu-rules.md и README Core. Текущие Core0.7.0/Hotbuild0.6.0; игровая проверка меню ожидается.
- Меню также открывается биндом: начальный Ctrl-Alt-C, если свободен; изменение и снятие — Claret → Claret Core. `MenuKey.lua`, стабильный ID ClaretCore_OpenMenu; единственный источник назначения — штатные карты FAF, захват комбинации в Claret временный. Не добавлять параллельный OptionValue для той же комбинации.

## Технические ориентиры
- Факт: установлен FAF3840, архив исходников C:/ProgramData/FAForever/gamedata/lua.nx2; версии ReUI Main1.3.2, Core1.7.0, Options1.2.0. Локальная копия ReUI отличается по версии. Источники: reui-notes.md, tech-findings.md, mod-inventory.md.
- Решение для прототипа: использовать ReUI, небольшую собственную основу Core. Options API сверять с установленной версией; не переносить API из более новой копии без проверки. Источник: library-recommendation.md, reui-notes.md.
- FAF Lua: table.getn, import, math.mod; осторожно с отсутствующими глобалами/полями модулей и лимитом upvalue. Отписывать события и освобождать контролы. Данные выбранных юнитов при OnSelectionChanged брать из параметра события. Источники: tech-findings.md, friend-notes.md, AGENTS.md.
- Сохранять настройки по событию через профиль; стабильные ID и порядок команд сохранять при обновлении. Выбранную клавишу хранит штатное меню игры. Источники: hotbuild-research.md, ../mods/ClaretHotbuild/modules/Keys.lua, Runtime.lua.
- При добавлении аналогов фракций не угадывать ID по префиксу; соответствия могут отсутствовать или быть неоднозначными. Проверять buildability выделенных юнитов. Источники: hotbuild-research.md, ../mods/ClaretHotbuild/modules/Equivalents.lua.

## При сверке
- Учёт состава и версий модов: mod-inventory.md; список особенностей: feature-catalog.md; зависимости: dependency-map.md; лицензии и авторы: license-audit.md и ../Credits and more/CREDITS.md.
- Проверка производительности: performance-hotspots.md и AGENTS.md. Нужны одинаковые сценарий, версия игры и три прогона; измерения и запуск игры выполняет пользователь.
- Достоверность: отличать факты, предположения и неизвестное. Локальные заглушки и разбор Lua не подтверждают игровой UI. История проверок и незавершённые вопросы: Stage/stage-1-research.md.

Актуальное уточнение: Core0.8.0 / Hotbuild0.7.0 — редактор встроен в раздел Hotbuild через definition.inline(parent, layout), без отдельной кнопки/окна. Общее меню расширяется под редактор и уменьшается в Core; CanLeave(intent) защищает черновик. Подробности и ограничения геометрии — Context/menu-rules.md.

Новое уточнение Core0.9.0: размер всех разделов меню одинаковый большой (1368×1320 до общего масштаба), без затемнения карты и без закрытия по нажатию снаружи. Это заменяет прежнее описание расширения/сжатия. См. Context/menu-rules.md.

Hotbuild0.8.0 поддерживает сохранённые игровые строительные шаблоны в выборе зданий через modules/TemplateCatalog.lua. Content ID сохраняется в прежних entries/grid; источник build_templates остаётся отдельным. Переименование/перестановка безопасны; изменение геометрии/состава или удаление требует повторного выбора. Adapter размещает копию шаблона штатным SetActiveBuildTemplate, когда инженер способен построить весь состав. Не угадывать фракционные аналоги шаблонов. Подробнее — Context/hotbuild-rules.md и README Hotbuild.

Hotbuild0.9.0: межфракционная конвертация шаблонов встроена в TemplateCatalog и Equivalents. Только полные однозначные соответствия, геометрия/порядок сохраняются; исходные шаблоны не меняются. Старую строку нужно повторно выбрать и сохранить для заполнения остальных фракций. Подробности — Context/hotbuild-rules.md и README Hotbuild.

Актуально на 2026-11-11: Core 0.10.0 и Hotbuild 0.10.9 (см. mod_info.lua и Main.lua). Иерархия «Строители», приоритеты смешанного выделения и поведение диалога совместимости описаны в README Hotbuild и последних записях Stage/stage-1-research.md; прежние номера версий и сценарии смешанного выделения в исторических записях не являются актуальной спецификацией. Для пустого выделения доступны массовые выборы авиации, армии, флота, экспериментальных объектов, транспортов, TML/ядерных шахт, мобильных щитов/стелса/MML и T3 артиллерии. Последовательные бинды инженеров T1/T2/T3/всех уровней добавляют ближайшего к курсору ещё не выделенного инженера. Добавлены двойные действия выбора ACU/транспорта, улучшение структуры под курсором и улучшение добытчика с выбором следующего ближайшего. Политики конфликтов и ручного восстановления старых назначений описаны в README Hotbuild. Пользователь бегло проверил изменения и сообщил, что в целом всё функционирует; подробная проверка каждого сценария не проводилась.

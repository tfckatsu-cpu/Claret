Загрузка мода и хуки
[✓] Файл в hook/lua/ui/game/X.lua дописывается в конец оригинального файла, а не заменяет его. Поэтому хук видит local-переменные оригинала и может переопределять его функции. Это основной механизм.
[✓] Хуки через папку hook не действуют на модули, загруженные ещё в лобби: layouthelpers, Bitmap, Text, Grid из lua/maui. Их можно только патчить на лету (подменять функции в уже загруженной таблице модуля). Для этого в моде отдельный patches.lua, который запускается из хука gamemain.lua до создания интерфейса.
[✓] Точка входа — хук gamemain.lua: патчи ставятся до CreateUI, основной код (core.Init) — после. Мелкие хуки (tabs.lua, score.lua, massfabs.lua, recall.lua, orders.lua, unitview.lua, keymap/misckeyactions.lua) нужны только чтобы получить доступ к локальным объектам конкретной панели.
[✓] Пути внутри кода — /mods/<имя папки>/..., с пробелом работает. При переименовании папки (1DNOMOD → DNO MOD) пришлось менять все импорты; uid в mod_info.lua менять не нужно и не стоит (по нему клиент узнаёт мод).
[✓] ui_only = true — мод не требуется у других игроков, работает и в рейтинге.
[✓] Диалект Lua 5.0 в FAF: for k, v in tbl do без pairs, оператор !=, math.mod, arg/unpack(arg) вместо .... Модули — таблицы с запретом обращения к несуществующим полям: чтение несуществующего глобала или поля модуля = ошибка, нужны rawget/rawset.
[✓] Лимит 32 upvalue на функцию. Большая функция окна настроек упёрлась в него (v217: «too many upvalues», окно перестало открываться). Решение — переменные уровня файла делать полями модуля, а не local.
[✓] Игра подхватывает новые файлы мода только при новом матче; если часть файлов обновилась, а часть нет (сбой копирования), получаются странные ошибки в окне настроек. Поэтому после каждого выпуска сверяю файлы на компьютере с моими по размеру/контрольной сумме.
Окна и сохранение настроек
[✓] Настройки хранятся в профиле игрока (Game.prefs) через Prefs.GetFromCurrentProfile / SetToCurrentProfile + SavePreferences. У мода несколько ключей: UIPanelTuner (все панели, с версией формата позиций), DNOMOD_* (звуки, SMD, флаги и т.д.), ключ окна настроек. Ключ панелей сознательно не менялся с v54, чтобы старые настройки подхватывались.
[✓] Настройки живут на каждом компьютере отдельно, с папкой мода не переносятся.
[✓] При смене формата хранения (например, порядок строк приоритетов «снизу вверх» → «сверху вниз») нужен одноразовый флаг миграции в prefs, иначе данные переворачиваются при каждой загрузке.
[✓] Выбор из списка лучше хранить по имени/идентификатору, а не по номеру — при изменении списка номер сбивается (сделано для звуков).
[✓] Окно на базе maui/window.lua само масштабирует минимальный размер; если масштабировать ещё и в своём коде, на 4K минимум становится больше экрана и окно «растягивается до упора» при любом ресайзе.
[✓] Прокрутка в окне: колесо, бегунок, клик по дорожке — реализуется вручную, готового скролл-контейнера для произвольных элементов нет.
[✓] Окно настроек должно строиться устойчиво: если одной регулировки нет (ошибка в середине), падает всё окно. Поэтому построение разбито на защищённые куски.
[✓] Частое SavePreferences стоит заметного времени (perf считал число и время сохранений) — сохранять по событию, не по таймеру.
Как устроен интерфейс (что оказалось неочевидным)
[✓] Позиции — LazyVar: пересчитываются только когда меняется зависимость, а не каждый кадр. «Пересчёт 100 раз в секунду» в целом не происходит; исключение — окно информации о юните, которое игра двигала каждый кадр (остановлено модом).
[✓] Игра в стартовой анимации записывает в край панели готовое число вместо привязки, и результат зависит от частоты кадров — отсюда «случайно» прыгающая панель фильтров. Решение — убрать анимацию и запоминать исходную привязку каждого края; есть ForceLV, чтобы игра не перезаписывала LazyVar.
[✓] Прозрачность родителя наследуется детьми: если спрятать рамку через alpha, пропадают кнопки на ней. Нужно скрывать именно картинку, а не контейнер.
[✓] Картинки нельзя поворачивать. «Стрелка вниз» — перевёрнутая верхняя.
[✓] Всплывающие элементы (подсказки, меню) рисуются далеко выше панели по Depth — при поиске «содержимого панели» их надо отбрасывать, но у кнопок приказов свой высокий слой, и это правило их ломало.
[✓] Миникарта — отдельная 3D-камера движка; её прозрачность изменить нельзя, функций для этого нет. Интерфейс не знает положение всех юнитов (только выделенные и под курсором), так что своя карта невозможна.
[✓] UI-мод не может заменить текстуры/модели юнитов; 3D-объекты «только себе» — через WorldMesh. UserUnit не отдаёт поворот юнита.
[✓] Игра даёт счёт на панели только если в лобби включён Score (иначе −1).
[✓] Связь между UI-модами разных игроков — только скрытые сообщения чата (SessionSendChatMessage + RegisterChatFunc по метке; ≤1024 байт, мимо симуляции, не в реплей). На одну метку — один обработчик, последний побеждает. Так работают Notify и TIS.
[✓] Голосование «Сдаться»: интерфейс получает только числа, пофамильно голоса знает лишь симуляция; «кто как голосовал» пришлось выводить через сообщения модам союзников и вывод по числам.
[✓] Клиент FAF передаёт игре только имя папки карты; остальное игра достраивает сама (это из соседней задачи с картой, но важно для понимания путей).
[?] Как именно движок решает, в какой кадр применить изменение LazyVar при анимациях — не знаю, только обошёл.
Конфликты и проблемы
[✓] В самом FAF есть баг: запасной вариант скрытия панелей обращается к несуществующей переменной, поэтому фильтры/пинги не скрывались. Мод скрывает сам.
[✓] «Game object has been destroyed» после гибели командира / в конце игры — мод работал с уничтоженными контролами. Все проходы вверх по родителям теперь через защищённый GetParent; мод останавливается при закрытии интерфейса.
[✓] Встроенный «Advanced target priorities» (Strogo): если включён и оригинальный мод (по uid), встроенная часть не ставится. Prefs-ключ тот же, настройки подхватываются.
[✓] Если TIS включён у игрока вместе с нашим модом, оба займут метку TIS и останется один обработчик — решено «уступать» канал.
[✓] GetFrame(1) без второго монитора роняет игру (ACCESS_VIOLATION, pcall не спасает). Нужна проверка GetNumRootFrames() >= 2. Это был вылет v381 у друга.
[✓] Лог может не писаться, если имя пользователя Windows кириллицей — учтено.
[~] Hotbuild, UMT, ReUI не конфликтуют напрямую — в логах ошибок от них не было, но целенаправленно совместимость не тестировалась.
[?] Поведение с другими модами, меняющими те же панели (например, другие «UI-перестройщики»), не проверялось.
Производительность
[✓] Каждая перехваченная ошибка Lua (pcall + error) не бесплатна: движок пишет полный стек (~5 КБ) в список исключений. У друга — 2531 ошибка за 5 минут, лог 13 МБ, память росла ~2,5 МБ/мин, проход прозрачности 33 мс. Правило: в частых местах не ловить «ожидаемые» ошибки, а проверять поля; глобалы читать через rawget(_G, ...). После исправления — ~50 ошибок за 20 минут.
[✓] Нагрузка мода: ~10,8 % времени кадра (26.10) → 6 % после перевода на «пересчёт только при изменениях». Самые тяжёлые части: окно юнита при наведении, компактные рамки, цифры реклейма, прозрачность, поиск панелей, позиции противников.
[✓] Большие подвисания (0,4–0,9 с) у друга — не от мода: в этих кадрах мод работал 0–3 мс, они есть и с выключенным модом; часть — сборка мусора Lua (падение памяти на 7–11 МБ), часть — сворачивание окна. Исключение: первый проход мода на старте подвешивает игру ~0,4 с.
[✓] FPS мод при этом снижает заметно (93–98 → 60–80 в первые минуты): проход по всем панелям раз в ~0,3 с за один кадр (9 мс в среднем, до 20+) даёт рывки; VSync при 144 Гц превращает +1 мс в −7 мс; мод добавляет ~1170 элементов интерфейса (2120 против 948). План — разнести проход по кадрам с бюджетом 1–2 мс.
[✓] Прозрачные остатки стандартных рамок почти ничего не стоят; дорого именно периодическое «выискивание» их.
[✓] WaitSeconds(n) в UI ждёт кадры по оценке AvgFPS — «10 секунд» могут быть и 20 реального времени. Профильных часов у FAF 3840 нет, только CurrentTime.
[✓] Приказы перебирались дважды за проход — 3,2 мс/с, сведено к одному.
[~] Симуляция идёт в отдельном от интерфейса потоке, поэтому UI-мод влияет на FPS, но не на скорость игры для всех. Из этого исходил, напрямую не проверял.
[?] Насколько реально 1170 лишних элементов влияют на рендер — не измерял, только посчитал.
Тестирование
[✓] Запустить игру самостоятельно я не могу (нужен ваш компьютер и игра). Цикл: синтаксис → тесты-имитации → выпуск → вы играете → я читаю game*.log.
[✓] Синтаксис: texluac -p после замены != на ~=; там же texluac -l для контроля upvalue (не больше 33 по счёту 5.1 — у движка лимит 32).
[✓] Имитация движка в dev/sim/test*.lua (texlua, заглушки LazyVar/контролов, несколько масштабов 1.0/1.25/1.75) — ловит логику раскладки, порядок, миграции, голосование. Не ловит: то, как игра реально рисует, Depth, анимации, тайминг.
[✓] Рендер «как в игре» для картинок — свои дампы контролов → PNG/GIF через Python, чтобы показать вам варианты до запуска.
[✓] В логе ищу: DNO MOD, warning:, Error, Evaluating LazyVar failed, too many upvalues, stack traceback. Диагностические строки мода (DNO MOD thin/perf/fpscheck/flags) включаются флагом; для финальной версии их нужно выключить.
